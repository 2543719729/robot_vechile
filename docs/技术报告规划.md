## 第一章：导航系统改进

### 1.1 导航算法切换：从DWA到TEB

#### 1.1.1 背景与动机
- **原有方案**：使用DWA（Dynamic Window Approach）局部规划器
- **存在问题**：
  - 精度控制不够理想
  - 在复杂环境中的路径规划能力有限
  - 难以满足高精度导航需求（2cm以内）

#### 1.1.2 TEB算法介绍
- **TEB（Timed Elastic Band）**：基于时间弹性带的局部路径规划算法
- **核心优势**：
  - 支持多目标优化（时间、距离、平滑度）
  - 更好的障碍物规避能力
  - 支持全向移动机器人
  - 丰富的可调参数

#### 1.1.3 关键参数配置
根据项目实际配置（`teb_local_planner_params.yaml`），需要详细说明以下参数：

| 参数类别 | 关键参数 | 作用说明 |
|---------|---------|---------|
| 速度参数 | max_vel_x, max_vel_y, max_vel_theta | 控制机器人最大速度 |
| 加速度参数 | acc_lim_x, acc_lim_y, acc_lim_theta | 控制加速度限制 |
| 目标容差 | xy_goal_tolerance, yaw_goal_tolerance | 到达目标的精度要求 |
| 轨迹参数 | dt_ref, max_global_plan_lookahead_dist | 轨迹规划的时间分辨率和前瞻距离 |
| 障碍物处理 | min_obstacle_dist, inflation_dist | 障碍物安全距离 |
| 优化权重 | weight_obstacle, weight_viapoint, weight_optimaltime | 多目标优化权重 |

### 1.2 精度控制挑战与解决方案

#### 1.2.1 问题分析
- **目标精度**：2cm以内
- **TEB局限性**：
  - TEB作为局部规划器，主要关注路径跟踪和避障
  - 在接近目标点时，由于速度衰减和控制频率限制，难以实现厘米级精度
  - `xy_goal_tolerance` 参数设置过小会导致机器人在目标点附近振荡

#### 1.2.2 解决方案：PID精确控制阶段
- **设计思路**：在机器人到达目标点附近后，切换到PID控制模式进行精确调整
- **实现方案**：
  1. TEB导航阶段：负责从起点到目标点附近的路径规划和跟踪
  2. PID精调阶段：当距离目标点小于阈值（如10cm）时，切换到PID控制
  3. 精确定位：通过PID控制器精确调整位置和姿态

## 第二章：Optuna自动参数调优系统

### 2.1 系统概述

#### 2.1.1 为什么需要自动调参
- TEB算法参数众多（30+个可调参数）
- 参数之间存在复杂的相互影响
- 手动调参耗时且难以找到最优组合
- 需要在多个目标（精度、速度、稳定性）之间权衡

#### 2.1.2 Optuna框架介绍
- **Optuna**：高效的超参数优化框架
- **TPE算法**：Tree-structured Parzen Estimator，贝叶斯优化方法
- **核心优势**：
  - 智能采样，比随机搜索更高效
  - 支持剪枝，提前终止不良试验
  - 支持分布式训练

### 2.2 开发历程与问题解决

#### 2.2.1 第一阶段：基础框架搭建
- **实现内容**：
  - 搭建Optuna优化框架
  - 定义参数搜索空间
  - 实现导航性能评估函数
  - 集成Gazebo仿真环境

- **遇到的问题**：参数无法实时刷新
  - **问题描述**：修改YAML配置文件后，move_base节点不会自动加载新参数
  - **影响**：每次试验使用的都是相同的参数，导致训练数据无效
  - **表现**：所有trial的导航表现几乎相同

#### 2.2.2 第二阶段：实时参数刷新
- **问题根因分析**：
  - ROS参数服务器的参数在节点启动时加载
  - 仅修改YAML文件不会触发参数更新
  
- **解决方案**：使用Dynamic Reconfigure
  - 实现`apply_params_dynamically()`函数
  - 通过dynamic_reconfigure客户端在线更新参数
  - 无需重启move_base节点即可生效

- **关键代码实现**（`optuna_nav_optimizer.py`）：
  ```python
  # 初始化dynamic_reconfigure客户端
  dynreconf_servers = {
      'teb': '/move_base_node/TebLocalPlannerROS',
      'global_inflation': '/move_base_node/global_costmap/inflation_layer',
      'local_inflation': '/move_base_node/local_costmap/inflation_layer',
      ...
  }
  
  # 在线更新参数
  self.dynreconf_clients['teb'].update_configuration(teb_params)
  ```

#### 2.2.3 第三阶段：并行训练优化
- **动机**：单线程训练效率低，无法充分利用计算资源
- **实现方案**：
  - 支持多Worker并行训练
  - 使用共享数据库（SQLite/MySQL）存储优化结果
  - 每个Worker使用独立的ROS端口和Gazebo实例

- **启动脚本**（`server_train.sh`）：
  ```bash
  # 单Worker训练
  ./server_train.sh
  
  # 4个Worker并行训练
  ./server_train.sh --workers 4
  ```

- **关键技术点**：
  - 端口隔离：`ROS_MASTER_PORT=$((11311 + WORKER_ID))`
  - 参数目录隔离：每个Worker使用独立的参数目录
  - 数据库同步：所有Worker共享同一个Optuna Study

### 2.3 优化目标与评估指标

#### 2.3.1 多目标优化
| 指标 | 权重 | 说明 |
|-----|------|-----|
| 精度 (Precision) | 45% | 到达目标点的位置误差 |

| 时间效率 (Time) | 15% | 导航完成时间 |
| 窄通道能力 (Narrow) | 8% | 通过狭窄区域的能力 |

#### 2.3.2 卡顿检测机制
- **检测维度**：
  - 低速持续时间
  - 无进展时间
  - 速度命令不匹配
  - 振荡事件
  - 急停次数

#### 2.3.3 测试场景设计

## 第三章：视觉识别系统

### 3.1 人脸识别模块概述

#### 3.1.1 功能描述
- 基于ROS的人脸识别功能
- 支持多人脸检测与识别
- 交互式识别模式

#### 3.1.2 技术架构
```
摄像头输入 → 图像预处理 → 人脸检测 → 特征提取 → 人脸匹配 → 识别结果
```

### 3.2 核心技术实现

#### 3.2.1 依赖库
- **face_recognition**：基于dlib的人脸识别库
- **OpenCV**：图像处理
- **cv_bridge**：ROS图像消息转换

#### 3.2.2 人脸编码与匹配
- **编码过程**：使用128维特征向量表示人脸
- **匹配算法**：计算欧氏距离，设置容差阈值（默认0.5）
- **置信度计算**：`confidence = (1 - distance) * 100`

#### 3.2.3 关键参数
| 参数 | 默认值 | 说明 |
|-----|-------|-----|
| camera_id | 0 | 摄像头设备ID |
| tolerance | 0.5 | 人脸匹配容差（0.4-0.6，越小越严格）|
| use_direct_camera | true | 是否直接使用摄像头 |

### 3.3 系统集成

#### 3.3.1 ROS话题
- `/camera/image_raw`：摄像头图像输入
- `/face_recognition/result`：识别结果输出

#### 3.3.2 使用流程
1. 训练人脸模型：`rosrun face_recognition_pkg train_faces.py`
2. 启动识别节点：`roslaunch face_recognition_pkg face_recognition.launch`
3. 交互式识别：输入`yes`进行识别

## 第四章：语音识别与交互系统

### 4.1 系统概述

#### 4.1.1 功能模块
语音交互系统基于讯飞AIUI平台，提供三大核心服务：

| 服务 | 功能 | 接口 |
|-----|------|-----|
| 语音合成 (TTS) | 文字转语音 | robot_tts.srv |
| 语音听写 (IAT) | 语音转文字 | robot_iat.srv |
| 语音理解 (NLU) | 语义理解与意图识别 | robot_semanteme.srv |

### 4.2 语音合成服务 (TTS)

#### 4.2.1 服务接口
```
# robot_tts.srv
请求:
  string text    # 要合成的文本
  bool play      # 是否播放合成的音频
响应:
  string audiopath  # 合成音频所在的路径
```

#### 4.2.2 应用场景
- 导航播报：到达目标点后播报介绍信息
- 交互反馈：语音回复用户指令

### 4.3 语音听写服务 (IAT)

#### 4.3.1 服务接口
```
# robot_iat.srv
请求:
  string audiopath  # 要听写的音频所在路径
响应:
  string text       # 听写完成的文字信息
```

#### 4.3.2 技术特点
- 支持离线/在线识别
- 支持中文普通话识别

### 4.4 语音理解服务 (NLU)

#### 4.4.1 服务接口
```
# robot_semanteme.srv
请求:
  int32 mode         # 模式：1=文字输入，2=音频输入
  string textorpath  # 文字内容或音频路径
响应:
  string tech        # 技能类型：system/user
  string iat         # 听写内容
  string anwser      # 语义识别后的回答
  string intent      # 自定义意图
  string[] slots_name   # 语义实体名称
  string[] slots_value  # 语义实体值
```

#### 4.4.2 自定义意图
| 意图 | 说明 | 语义实体 |
|-----|------|---------|
| robot_nav | 机器人导航 | action_move（导航到/带我去）, nav_pos（目标地点）|
| robot_control | 机器人控制 | robot_control（左转/右转/前进/后退）, number（数值）, unit_length（单位）|

### 4.5 语音导航集成

#### 4.5.1 voice_nav模块
- **功能**：将语音指令转换为导航目标
- **实现**：`voice_nav.cpp`

#### 4.5.2 支持的语音指令
- 导航到指定展馆："带我去深圳馆"
- 返回起点："回去充电"
- 取消导航："取消导航"
- 整体游览："带我参观一下"

#### 4.5.3 导航点配置
导航点信息存储在`position_info.txt`文件中，包含：
- 位置名称
- 坐标 (x, y)
- 朝向 (orientation_z, orientation_w)
- 介绍文本
